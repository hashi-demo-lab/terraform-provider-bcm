# Implementation Plan: CMKube API Alignment

**Branch**: `102-cmkube-api-alignment` | **Date**: 2026-01-09 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/102-cmkube-api-alignment/spec.md`

## Summary

Align the `bcm_cmkube_cluster` Terraform resource with the actual BCM KubeCluster API entity structure by:
1. Refactoring the resource to match real BCM API fields (network UUIDs, etcd_cluster reference, app_groups)
2. Creating a new `bcm_cmetcd_cluster` resource for EtcdCluster entity management
3. Adding `kubelet_role` and `etcd_host_role` nested blocks to `bcm_cmdevice_device` for role-based node assignment

This is a **breaking change** that removes non-functional fields (`master_nodes`, `worker_nodes`, `dns_servers`, `cni_plugin`, etc.) and introduces the correct BCM API entity model.

**Target Platform**: Linux, macOS, Windows (multi-platform provider)
**Project Type**: Single Go module - Terraform Provider
**Performance Goals**:
- API calls complete within BCM timeout limits
- Resource operations complete within Terraform default timeouts

**Constraints**:
- Must maintain backward compatibility where possible via deprecation warnings
- BCM cmkube API requires client-generated UUIDs
- BCM returns null/empty for write-only fields (node lists not returned by getKubeCluster)
- Role assignment is via embedded roles in Device entity (updateDevice), not separate API

**Scale/Scope**:
- 3 resources modified/created
- ~15 new schema attributes per resource
- ~30 new acceptance tests
